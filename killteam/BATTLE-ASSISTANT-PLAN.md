# 미션 생성과 전투 보조 확장안

작성: 2026-10-14. 이 문서는 다음 개발 설계이며, 해당 기능은 아직 앱에 구현하지 않았다.

## 방향

미션 생성 → 게임 준비 → 전투 보조 → 결과 기록을 하나의 게임 세션으로 연결한다. 기존 펼쳐보기 데이터시트, 무기 규칙 팝업, 스크롤 네비게이터, 검정·주황·회색 톤을 그대로 사용한다. AR·온라인 대전·서버 동기화는 초기 범위에 포함하지 않는다.

Kill Team 2024는 규칙 판본이고 Approved Ops 2025는 미션팩이다. 이를 같은 버전 번호로 취급하지 않는다. 조사에서 확인한 공식 Approved Ops 2025 자료를 우선 지원 후보로 삼되 현재 최신 팩이라는 주장은 하지 않는다. 구현 착수 시 공식 배포 자료와 정오표로 사용 버전을 확정한다.

## 벤치마킹

| 참고 | 확인한 기능 | 적용할 설계 |
|---|---|---|
| 공식 40K 앱 Command Bunker | 선택한 군대의 규칙을 모아 빠르게 조회 | 선택 로스터의 무장·능력·플로이·장비만 전투 화면에 노출 |
| 공식 40K 앱 War Journal | 게임 기록, 상대 규칙 조회 | 세션 저장·재개, 상대 간단 정보, 결과 기록 |
| KTDash | 로스터, Wounds·CP·TP·VP 추적 | 오퍼레이티브 카드에 전투 상태 조작 연결 |
| KTDojo | 준비 흐름, CP·TP·VP·Tac Ops·피해 추적, 미션 맵 | 준비 체크리스트와 배치도·득점 기록을 연결 |
| KT Codex | 데이터카드와 키워드 설명 접근 | 전투 중 데이터시트를 같은 화면에서 펼치고 규칙 팝업 사용 |

공개 기능 소개를 기준으로 조사했다. 각 앱의 실제 전체 화면을 조작해 평가한 것은 아니다. 특정 앱의 UI 자산이나 코드를 복제하지 않는다.

## 1. 미션 카드 / 미션 생성

첫 화면: `게임 시작` → 내 로스터 선택 → 상대 팀/이름 → 미션팩·킬존 → 미션 구성 → 준비 완료.

- **Crit Op:** 공유 미션. 미션팩이 허용하는 무작위 생성, 수동 선택, 대회 지정 모드를 제공한다.
- **배치·맵:** 선택한 킬존과 호환되는 맵만 보여준다. 미션팩에서 맵과 목표가 결합되어 있으면 조합 단위로 생성한다. 서로 독립이라고 추정하여 섞지 않는다.
- **Tac Op:** 아키타입과 팩 버전을 기준으로 후보를 제한한 뒤 선택한다. 무작위 추천은 별도 연습 옵션이며 공식 선택 절차로 표시하지 않는다.
- **Primary Op:** 별도 선택 및 공개 상태로 관리한다. 점수 계산 방식은 해당 팩의 규칙을 검증한 뒤 적용한다.
- **선제권 관련 카드:** 선택 팩에 있는 경우 보유·사용 상태를 기록한다. 지급 시점과 효과는 버전별 정의를 따른다.
- 생성 결과를 확정하면 게임에 저장한다. 변경은 명시적인 재설정 동작으로 하고 재추첨 이력을 남긴다. 전투 중 우발적으로 카드가 바뀌지 않게 한다.
- 숨겨야 하는 선택은 초기 비공개로 저장하고 공개 버튼을 둔다. 같은 기기를 공유하는 경우 가림막 화면을 사용한다. 이는 편의상 가림이지 인증 보안 기능은 아니다.
- 카드 형식: 검은 이름 헤더 → 주황 유형 띠 → 밝은 조건·득점 본문 → 버전/출처. 영문 원본과 한국어 번역 분리.

현재 영문 팀 데이터에서 Angels of Death는 Security/Seek And Destroy, Scout Squad는 Infiltration/Recon이다. 현재 TypeScript Team 모델에는 archetypes가 없으므로 추가하고 표기를 정규화해야 한다.

## 2. 게임 준비

팩에서 정의한 실제 Game Sequence 순서대로 체크리스트를 만든다. 일반적인 입력 항목은 로스터·오퍼레이티브·전술·장비·미션·배치·비공개 목표·시작 상태이며, 그 순서를 임의로 공식 규칙으로 단정하지 않는다.

준비 단계에 선택 팀의 관련 규칙 바로가기를 제공한다. 예를 들어 Scout Forward Scouting, Angels Chapter Tactics는 해당 항목에서 확인 가능하도록 한다. 자동으로 효과를 발동하거나 전략적 선택을 대신하지 않는다.

상대 로스터는 선택사항이다. 상대가 앱을 사용하지 않아도 상대 이름·팀·CP·VP만 기록하며 게임을 시작할 수 있다.

## 3. 전투 보조

하단 메뉴는 `로스터 / 전투 / 검색 / 설정`으로 구성하고 팀 참고는 로스터 화면 안에서 접근한다. 게임이 없으면 전투 탭에 시작 버튼, 진행 게임이 있으면 이어하기를 보여준다.

고정 상단에는 터닝 포인트, 현재 단계, 선제권, 양측 CP·VP를 표시한다. 그 아래 `오퍼레이티브 / 플로이 / 미션 / 기록`을 제공한다. 작은 화면에서 모든 숫자와 탭을 한 줄로 압축하지 않는다.

### 오퍼레이티브

접힌 카드에서도 남은 운드, Ready/Expended, Engage/Conceal, 전투불능 상태를 확인하고 조작한다. 펼치면 현재 데이터시트가 나온다. 운드 버튼은 0~최대 범위에서 조작하며 0일 때 전투불능 표시를 제안하되 특수 규칙 처리를 위해 사용자가 확정한다. 피해·회복·명령·활성화 변경은 되돌릴 수 있게 한다.

미니어처 운드를 화면에서만 변경해도 충분하다. 처음에는 명중/방어 굴림 판정이나 거리·시야 판단을 자동화하지 않는다. 부상 상태는 검증한 규칙으로 표시할 수 있지만 자동 능력치 변경은 별도 검증 전까지 적용하지 않는다.

### 플로이와 능력

선택 팀의 전략 플로이와 교전 플로이를 분리한다. 수동으로 검수한 timing 태그만 이용해 현재 시점의 후보를 위에 놓는다. `전체 보기`는 항상 제공한다. 원문을 단순 키워드 검색해 사용 가능/불가능을 확정하지 않는다.

`사용` 버튼은 CP 비용·사용 횟수·효과 지속 상태를 기록한다. 0CP 대체, 특정 캐릭터/장비 예외는 선택한 이유를 기록하고 실사용 비용을 확정한다. 상시 능력에는 사용 버튼을 만들지 않는다. 사용 기록을 취소하면 CP와 횟수가 함께 복구된다.

### 미션과 득점

Crit/Tac/Kill 점수를 양측·터닝 포인트별로 나누어 기록한다. Primary 계산은 검증한 미션팩 규칙으로 적용한다. 미션 조건 옆에 `득점 기록`을 두고 합산은 자동 처리하되 실제 조건 충족 여부는 플레이어가 판단한다. 자동 판정에 필요한 거리·상대 행동·목표 통제는 현재 앱이 알 수 없기 때문이다.

고정 맵 이미지는 확대 가능하게 하고 목표 번호별 소유 상태/메모를 표시한다. 초기에는 드래그 지형 편집기를 만들지 않는다. 카드별 득점 한도·시작 가능 시점은 명시적 스키마와 검증된 데이터로 제한한다.

### 터닝 포인트 종료와 재개

종료 패널에서 미기록 점수와 지속 효과를 확인한다. 다음 TP 전환에 따른 CP/Ready/지속 효과 처리는 검증된 팩·핵심 규칙 정의만 사용한다. 같은 버튼을 두 번 눌러 CP를 중복 지급하지 않는다. 이전 TP로 되돌리면 전환 전 상태 전체를 복구한다. 운드나 전투불능을 무조건 초기화하지 않는다.

게임 시작 시 로스터와 데이터 버전의 스냅샷을 만든다. 원본 로스터 편집·데이터 업데이트가 진행 게임을 바꾸지 않는다. 자동 저장·새로고침 복원·게임 백업을 제공하며 초기에는 한 기기에서 수동으로 양측 정보를 기록한다.

## 4. 데이터와 구현 구조

killteamjson에서 현재 사용하는 팀 데이터만으로 미션팩 전체, 배치도, 득점·타이밍 규칙을 구성할 수 없다. 별도의 버전 관리 데이터가 필요하다. 커뮤니티 JSON을 공식 최신 데이터라고 표시하지 않는다.

```text
src/battle/types.ts         게임 세션·오퍼레이티브 상태·기록
src/battle/reducer.ts       조작과 되돌리기·TP 전환
src/battle/storage.ts       세션 저장·복원·백업
src/battle/scoring.ts       팩별 득점 계산
src/battle/generator.ts     호환 조합 생성·필터·확정
src/components/battle/     준비·전투·미션·기록 화면
public/data/mission-packs/  팩·카드·허용 조합·맵 참조
```

MissionPack에는 id/version/source/verifiedAt, gameSequence, 허용 조합과 scoring 정책을 둔다. MissionCard에는 유형, 영문 원본, 한국어 초안, 아키타입/킬존 제약, 득점 시점/한도, 공개 규칙을 둔다. BattleSession에는 rosterSnapshot, teamDataVersion, missionPackVersion, 선택 미션, 양측 상태, TP·단계·선제권, scoreEvents, 사용 횟수·지속효과, actions를 둔다.

현재 규모에서는 기존 로컬 저장 방식을 재사용한다. 이미지/기록량이 커지면 IndexedDB로 이전한다. 모든 수치는 중앙 reducer에서 변경하여 버튼마다 CP·VP 상태를 따로 관리하지 않는다. 무작위 추천은 현재 허용 후보에서 균등하게 뽑고, 게임 구성의 draw history를 저장한다. 대회 지정은 랜덤을 사용하지 않는다.

공식 무료 자료로 검증 가능한 항목부터 지원한다. 미확보 카드 본문은 창작해 채우지 않고 사용자가 카드 이름·조건·득점 메모를 입력하는 사용자 카드로 구분한다. 사진 OCR, 온라인 미션팩 동기화, 계정은 이후 범위다.

## 5. 권장 개발 순서

1. **전투 보조 기반:** 로스터에서 게임 시작, 운드·활성화·명령·CP·수동 VP, 4TP 진행 UI, 저장·재개·되돌리기. TP 수는 기본 KT2024 정책이며 다른 팩은 설정으로 분리한다.
2. **미션 연동:** 검증한 팩 하나, 미션 구성·수동 선택·연습 무작위 모드, 아키타입 필터, 카드 표시, 득점 항목·비공개 목표, 정적 맵.
3. **규칙 기반 보조:** 플로이 타이밍·실제 CP 비용·제한 횟수, 일회성 능력, TP 전환 지속 효과. 번역/예외 규칙 검수 후 적용한다.
4. **후속:** 대전 기록·통계, 상대 로스터 가져오기, QR 공유, 선택적 양측 동기화.

첫 릴리스는 1과 제한된 2를 함께 묶고, 게임을 실제로 사용하면서 3을 확대하는 것이 좋다. 미션 자료 확보 전에는 수동 입력 모드로 진행할 수 있지만 이를 공식 카드 자동 뽑기 완료라고 보고하지 않는다.

## 6. 검증 기준

- 지원하지 않는 팩/킬존/아키타입 조합이 공식 모드에서 생성되지 않는다.
- 점수 한도, 비공개 선택의 공개, 수동 수정과 취소가 일관된다.
- CP가 음수가 되지 않으며 0CP 예외와 사용 취소가 비용·횟수 함께 처리된다.
- TP 중복 전환으로 CP가 증가하지 않는다. 되돌리기는 전체 상태를 복구한다.
- 종료 후 재접속·오프라인·새로고침에도 세션이 동일하게 복원된다.
- 로스터/번역 업데이트가 진행 게임의 스냅샷을 변경하지 않는다.
- 모바일에서 운드/명령 조작은 1회, 미션·플로이·데이터시트 조회는 1~2회 터치로 가능하다.
- 게임 시작 시점에 선택한 데이터·미션팩 버전과 검수 상태를 확인할 수 있다.
